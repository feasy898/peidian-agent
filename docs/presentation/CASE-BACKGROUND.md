# 案例背景 · 示范园区（PARK-001）一页纸

> 给观众的「厂区」代入材料。所有数字均为系统种子数据（`ontology/seed.yaml`，运行期只读），
> 演示中的每一次读数、每一条告警、每一张票都出自这份园区档案——先记住它，后面四条流都在这里发生。
> 配套演示方案见 `docs/presentation/DEMO-DESIGN.md`。

## 1. 园区概况

**示范园区**：一类制造园区，10kV 双回路电源进线，A/B 两座配电房，自己还投资了光伏、储能和充电桩。
当天为 **2026-09-15（周二）**，早班交接时间是 08:30——演示从值班员张工接班后的第一句话开始。

## 3. 电价与需量（经营侧）

- **合同容量 2000 kW**，按月最大需量计基本电费（REG-COMM · COMM-DEMAND-CHARGE：按需量与合同容量孰大）。
- **9 月已录最大需量 1720 kW** → 需量比值 **0.86**（1720/2000）。离需量预警线（比值 >1.0 发 P2）不远，
  下午负荷高峰（日负荷形状峰值系数 0.98×基准 1400 kW≈1.4 MW 级）是值班员最操心的事。
- **目录电价 TARIFF-2026A**（2026 全年有效，峰谷套利只允许引用本表——COMM-TOU-ARBITRAGE）：

| 时段 | 范围 | 电价（元/kWh） |
|---|---|---|
| 谷 | 00:00–08:00 | 0.35 |
| 平 | 08:00–10:00、12:00–18:00、21:00–24:00 | 0.70 |
| 峰 | 10:00–12:00、18:00–21:00 | 1.10 |

  峰谷价差 3 倍多——储能一度电低谷充、高峰放，毛差 0.75 元；但**跨时段边界那一瞬间的判定依据**
  是演示 F4 的考点（业务时钟，不是电脑时钟）。

## 6. 当天的「剧情线」（四条演示流的背景）

1. 08:30 张工接班，例行日巡检（F1）。
2. 上午 A 房 2 号变负载率被推高到 **0.83**（1328 kW/1600 kVA），PHYS-TX-LOAD P2 告警响起（F2 前半）。
3. 处置要走票：王工签发操作票、赵总审批，仿真分闸、环境回读确认（F2 后半）。
4. 期间张工试着「抄近路」——无票直切、改保护定值、绕审批——全部被网关物理拒绝（F3）。
5. 邻近午峰，张工问了一句电价成本（恰好卡在 11:59:50）；上午 A 房温湿度传感器还断过一次线（F4）。

## 7. 诚实边界声明（对观众明说）

- **物理模型是简化的**：负载率按「回路有功/额定容量」直算，温度缓升/遥信抖动/量测中断按事件注入近似
  （仿真层精度边界，spec M5 §2）——它验证的是**处置流程与安全纪律**，不是保护整定级仿真。
- **REAL 仅 mock 接线**：真实现场模式本期只有 mock 适配器（`tools/_base.py real_mock_execute`，
  「不触任何真实设备」）；评审期间 EVAL/黄金集强制仿真模式。这台演示机**发不出任何一个真实遥控报文**。
- **「智能体大脑」是脚本替身**：演示用发布物 rel-0001 的模型侧为离线脚本化回放（mock-scripted），
  动作申请/审批/执行/回读全部走真实模块链——演示可断网跑、逐字节重放。
- **黄金集是开发集**：12 条种子全部基于本园区；正式验收另持独立测试集（不在本仓库），开发期不可见。
