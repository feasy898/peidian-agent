## 3. 资产工程阶段新发现（非 v1→oracle 偏差，登记备处置）

### R-1〔基线漂移〕rel-0001 发布物 `evaluation/cases.yaml` 与 manifest 登记 hash 不符——resolve_release 完整性门禁按设计拒绝，CLI 只读复核模式当前报 ASSEMBLE REFUSED

- **现象（本会话实跑，2026-09-29，仓库根）**：
  `PYTHONPATH=src python -m m7_registry.assemble --release-id rel-0001` →
  `ASSEMBLE REFUSED: release 'rel-0001' 发布物完整性校验失败: evaluation/cases.yaml:
  sha256 与 manifest 不一致（内容被改动）`（`src/m7_registry/publish.py:289-314` 抛
  `ImmutableReleaseError`；`src/m7_registry/assemble.py:110-113,210-234` 转为 REFUSED 退出 1）。
- **根因（git 证据链）**：
  1. 发布时（2026-09-28T15:09:45Z，commit 19fc48b）manifest 登记 hash 正确——发布时点
     `evaluation/cases.yaml` 内容（git blob d0474b2f）的 CRLF 形态 sha256 =
     `431424c7ec4f…`，与 `releases/rel-0001/manifest.yaml:35` 登记值逐位一致；
  2. commit 06ce55a（2026-09-29 00:48，"SAFE 规程判据落地…mock 清单 schema 对齐"）对
     `tests/fixtures/mock_releases/rel-0001.yaml`、`tests/fixtures/mock_releases/mock-rel-0001.yaml`
     **和 `releases/rel-0001/evaluation/cases.yaml`** 三文件各改 14 行（case_004/010 弃自签
     改人工签发链）——发布物内证据快照被同步改写，而 manifest（按 SPEC-M7-05/12 只写一次
     纪律）未随之重发布，故 hash 失配；
  3. 当前发布物 `evaluation/cases.yaml` 实测 sha256 = `cdf55c0a5b65…`（与当前 fixture 逐字节
     相同）；其余四件（release.yaml/agent_contract.yaml/evaluation/report.json）hash 仍与
     manifest 一致。
- **定性**：M7 代码行为正确——resolve_release 篡改检测按 SPEC-M7-12 设计拒绝，恰为完整性
  门禁的实证；EVAL 套件 16/16 全绿不受影响（EVAL-M7-REL-P 在沙箱发布，hash 现算现校）。
  属**发布后证据快照越权同步改写**造成的仓库基线漂移（write-once 纪律在代码层无法阻止
  仓外直改，hash 复核正是为此设计并已拦截）。
- **影响面**：① `assemble` CLI 对 rel-0001 的只读复核（manifest 复核 + 签名 + 黄金重跑）
  被阻断；② M6 evaluator 按 `releases/rel-0001/evaluation/cases.yaml`（解析首位）重跑的
  案例清单与签名链绑定的归档（evaluation/report.json，未改动）不一致——重跑清单内容已不
  是签发 rel-0001 成绩时所用清单；③ `specs/README.md`/CHANGELOG 所记"CLI 复核 verify 模式
  12 种子重跑 1.0/97.67"在登记时点（2026-09-28，06ce55a 之前）为真，现已不成立。
- **处置建议（超出 M7 工程师权限，待资产工程 owner 裁决，二选一）**：
  a. 以 rel-0001 发布时点内容为准——还原 `tests/fixtures/mock_releases/{rel-0001,mock-rel-0001}.yaml`
     与 `releases/rel-0001/evaluation/cases.yaml` 至 19fc48b 版本（SAFE 判据改动经
     mock-rel-0001 单线承载，rel-0001 快照保持发布时点原样）；
  b. 承认基线更新——走 re-publish 流程（新 release id 重新走 assemble 全链），原 rel-0001
     目录内容还原为发布时点原样（不可原地改写）。
  无论哪种，`releases/rel-0001/manifest.yaml` 与其余四件发布物均不应改动。
- **v2 条款关联**：SPEC-M7-12（resolve_release 完整性复核）、SPEC-M7-16（CLI 只读复核模式
  ——规格中的"基线现状注记"已照实登记）。
